# Mainlining — Mövzu analizi

## 1. Məqsəd

Bu sənəd **Mainlining** üçün yoxlanmış Steam rəy məlumat toplusu, deterministik mövzu namizədləri və məna yönümlü audit nəticələrini birləşdirir.

Əsas araşdırma sualı:

> **Mainlining hacking + rəqəmsal araşdırma + dəlil təqdim etmə modelində oyunçuya həqiqi “özüm tapdım” hissi verirmi, yoxsa sistem yalnız əvvəlcədən müəyyən edilmiş konkret dəlil / şəxs / məkan kombinasiyasını qəbul etdiyi üçün araşdırma trial-and-error-a çevrilir?**

3. **analitik nəticə / hipotez** — həmin dəlillərin şərhidir.

# 6. Əsas güc: araşdırma fantasy-si işləyir

`DEPTH_CHALLENGE` və `INVESTIGATION_DISCOVERY` namizədlərində mənfi konsentrasiya baseline-dan aşağıdır.

Müsbət auditdə təkrarlanan təcrübə:

- display name-dən real şəxsə getmək;
- website → IP → sistem → file chain qurmaq;
- e-poçt, chat, xəritə və fayllardan kontekst toplamaq;
- adların və əlaqələrin sonrakı işlərdə yenidən tanış gəlməsi;
- kağız/qeyd ilə məlumatı birləşdirmək;
- “mən bunu özüm tapdım” hissi.

Ən yaxşı anlarda Mainlining özünü real texniki simulyator kimi yox:

> **rəqəmsal mühitdə yüngül detektiv / point-and-click araşdırma**

kimi yaxşı satır.

### Nəticə

> **Mainlining-in əsas dəyəri hacking əmrlərinin özündə yox, giriş əldə etdikdən sonra məlumatları əlaqələndirib nəticəyə gəlməkdədir.**

**Etibarlılıq: High**

# 7. Ən ciddi dizayn problemi: dəlilin sistem tərəfindən qəbulu

74 mənfi rəyin auditində ən güclü struktur pattern budur.

Oyunçu çox vaxt:

- doğru şübhəlini;
- real cinayəti;
- məntiqli və hətta daha güclü dəlili

tapır.

Amma arrest sistemi:

- yalnız developer tərəfindən konkret işarələnmiş file-i;
- konkret location-u;
- konkret person/evidence/location kombinasiyasını

qəbul edə bilir.

Rəylərdə təkrarlanan nümunə:

> “Məndə daha açıq-aşkar incriminating sənəd var, amma oyun başqa faylı istəyir.”

Bu, sadəcə puzzle difficulty deyil.

Bu, iki fərqli state yaradır:

```text
oyunçu bilir
≠
sistem qəbul edir
```

### Fundamental problem

Investigation oyununda oyunçu düzgün reasoning qurubsa, sistem mümkün qədər həmin **knowledge state**-i tanımalıdır.

Əks halda:

> **məntiqi nəticə çıxarma → gizli acceptance rule tapmağa**

çevrilir.

**Etibarlılıq: High**

---

# 8. Feedback problemi: səhv nədir?

Arrest submission üç əsas hissədən ibarətdir:

- şəxs;
- dəlil;
- məkan.

Mənfi rəylərdə təkrarlanan problem:

> kombinasiya səhv olduqda oyun hansı komponentin səhv olduğunu düzgün göstərmir.

Bəzi hallarda:

- yanlış location;
- zəif evidence;
- yanlış suspect

eyni və ya yanıltıcı nəticə mesajı yaradır.

Bu, failure-dan öyrənməni dayandırır.

### Sağlam failure loop

```text
hypothesis
→ action
→ dəqiq feedback
→ model düzəlişi
→ yeni hypothesis
```

### Mainlining-in zəif anı

```text
hypothesis
→ wrong
→ hansı hissə wrong bilinmir
→ başqa kombinasiyanı yoxla
→ brute force
```

### Nəticə

> **Failure mastery yaratmaq əvəzinə kombinator trial-and-error yarada bilir.**

**Etibarlılıq: High**

---

# 9. Cyber Manhunt və Need to Know ilə recurring pattern

Artıq üç müxtəlif oyun eyni fundamental problemi fərqli formada göstərir.

### Cyber Manhunt

```text
oyunçu cavabı bilir
≠
scripted clue trigger açılmayıb
```

### Need to Know

```text
oyunçu semantic olaraq düzgün qiymətləndirir
≠
sistem exact rule/evidence formatını qəbul etmir
```

### Mainlining

```text
oyunçu doğru suspect/crime anlayır
≠
sistem exact person/evidence/location kombinasiyasını istəyir
```

Bu artıq cross-game principle-dir:

> **Investigation sistemi interaction history-ni yox, mümkün qədər oyunçunun knowledge state-ni modelləşdirməlidir.**

**Etibarlılıq: High**

# 10. Terminal və input friction

`TERMINAL_UI`:

- 33 mention;
- 39.4% mənfi;
- baseline-dan **1.62×** yüksək.

Mənfi rəylərdə:

- sürətli yazanda düymələrin itməsi;
- copy/paste olmaması;
- cursor-u sola/sağa aparıb səhvi düzəldə bilməmək;
- yalnız son command history;
- səhv IP üçün “command not found” kimi qeyri-dəqiq error;
- eyni IP və filename-ları təkrar əl ilə yazmaq

tez-tez təkrarlanır.

Burada vacib distinction:

> **typing fantasy yaratmaq başqa şeydir, mətn redaktəsini qəsdən narahat etmək başqa.**

Hacking simulyasiyası tam real olmaq məcburiyyətində deyil.

Amma real command line görünüşü:

> real command-line affordance gözləntisi yaradır.

Bu Hacknet nəticəsini gücləndirir.

**Etibarlılıq: High**

# 11. Desktop UI — immersion və iş yaddaşı arasında konflikt

Müsbət rəylər:

- Windows XP/2009 hissini;
- parody software-ləri;
- pixel art;
- saxta browser və tətbiqləri

güclü immersion kimi görür.

Mənfi rəylər:

- pəncərələrin üst-üstə düşməsi;
- resize/minimize imkanlarının zəifliyi;
- click-through;
- bir pəncərəni scroll edəndə digərinin də scroll olması;
- notepad limitləri;
- qeydlərin case-lər arasında saxlanmaması

kimi problemləri vurğulayır.

Bu xüsusilə information game üçün vacibdir.

### Principle

> **Fictional OS özü oyunun əsas iş alətidirsə, onun pəncərə və qeyd sistemi oyunçunun external working memory-sinə çevrilməlidir.**

Mainlining vizual olaraq desktop fantasy-si yaradır, amma bəzi əsas desktop affordance-larını zəif təmin edir.

**Etibarlılıq: High**

# 12. Təkrarçılıq

`REPETITION` ən sərt deterministik riskdir:

- 18 mention;
- 12 mənfi;
- **66.7% mənfi**
- baseline-dan **2.74×** yüksək.

Mənfi və hətta bəzi müsbət rəylərdə əsas dövr belə təsvir olunur:

```text
website tap
→ ping / IP
→ hack
→ list
→ download
→ files oxu
→ repeat
```

Yeni case-lər:

- yeni şəxs;
- yeni mətn;
- yeni cinayət

verir.

Amma hacking action grammar çox az dəyişir.

### Nəticə

> **Mainlining Hacknet-də gördüyümüz command repetition problemini tam həll etmir; hacking burada əsas puzzle yox, hər araşdırmanın təkrarlanan giriş ritualına çevrilə bilir.**

**Etibarlılıq: High**

# 13. Realizm: tam həqiqilik tələb deyil

Maraqlıdır ki `REALISM_ACCURACY` özü yüksək mənfi konsentrasiya göstərmir.

Müsbət oyunçular:

- sadələşdirilmiş hacking-i qəbul edir;
- point-and-click / detective fokusunu problem saymır;
- technical simulation gözləmədikdə təcrübədən razı qala bilir.

Əsas problem:

> real olmaması yox, **öz daxili qaydalarının və UI davranışının ardıcıl olmaması**dır.

Yəni:

- IP/URL münasibəti sadələşdirilə bilər;
- command sayı az ola bilər;

amma:

- səhv error message;
- qəbul edilməyən məntiqli dəlil;
- itən input

etibarı sındırır.

### Principle

> **Seçilmiş həqiqilik tam realizmdən daha vacibdir; consistency isə realism-dən də vacibdir.**

**Etibarlılıq: High**

# 14. Hekayə və yazı

- 132 mention;
- 22.7% mənfi;
- baseline-a yaxın.

Bu, hekayənin neytral olması demək deyil.

Yaradıcı Sam Read character-i məhz yazı üslubundan tanıtmaq istədiyini bildirib. Bu niyyət bəzi rəylərdə işləyir.

### Nəticə

> **Mainlining-in hekayəsi əsas gücdür, amma Hacknet və Cyber Manhunt kimi zəif mexaniki dövrü sonsuz daşıyan səviyyədə dominant deyil.**

**Etibarlılıq: Medium-High**

# 15. Agency — iki fərqli növü ayırmaq lazımdır

Deterministik `PLAYER_AGENCY` siqnalı kiçik həcmdə müsbət görünür.

Müsbət rəylərdə:

- bəzən birdən çox suspect;
- müxtəlif evidence;
- fərqli case outcome-ları

haqqında tərif var.

Creator intent də hər case üçün müxtəlif nəticə və daha ağır/yüngül hökm variantlarını vurğulayır.

Amma bir çox rəy qeyd edir ki:

- story böyük ölçüdə lineardır;
- seçilən suspect/evidence uzunmüddətli hekayəni az dəyişir;
- replay value aşağıdır;
- “500 criminals” fantasy-si sandbox kimi açılmır.

Bu səbəbdən agency iki yerə ayrılır.

### Procedural competence

> “Düzgün şəxsi, dəlili və məkanı özüm tapdım.”

**Bu Mainlining-in real gücüdür.**

### Narrative agency

> “Mənim seçimim hekayənin gələcəyini dəyişdi.”

**Bu daha zəif və qeyri-bərabərdir.**

### Nəticə

> **Mainlining əsasən seçim fantasy-si yox, competence fantasy-si verir.**

**Etibarlılıq: High**

# 16. Məhsul vədi ilə real təcrübə

Cari Steam təsviri oyunçuya:

- “skill, judgement and cunningness”;
- case-in nə vaxt tamam olduğunu özün müəyyən etmək;
- çox erkən hərəkətdə böyük lead-i qaçırmaq;
- çox gec hərəkətdə suspect-in qaçması;
- 500-dən çox cinayətkar

kimi geniş investigation space göstərir.

Mənfi auditdə isə bəzi oyunçular:

- yalnız current mission target-ları ilə işləyə bildiyini;
- digər yüzlərlə NPC-ni real araşdıra bilmədiyini;
- hekayənin branch etmədiyini;
- konkret qəbul edilən cavabların olduğunu

vurğulayır.

Bu:

> **sandbox expectation → linear point-and-click reality**

uyğunsuzluğu yarada bilər.

Bəzi müsbət rəylər məhz gözləntini düzgün qurur:

> “Bu Hacknet deyil; hacking elementli point-and-click adventure-dır.”

### Nəticə

> **Mainlining-in satisfaction-u məhsulun nə olmadığı düzgün başa düşüldükdə artır.**

**Etibarlılıq: High**

# 19. Yaradıcı məqsədi vs oyunçu nəticəsi

## Intent: government-side hacking fantasy

Yaradıcı klassik rebel hacker əvəzinə dövlət agenti perspektivini seçib.

**Outcome:** güclü və fərqləndirici premise.

## Intent: puzzles əsas məqsəd olmasın, araşdırma/narrative işləsin

**Outcome:** müsbət oyunçular məhz point-and-click investigation hissini sevir.

## Intent: case-də müxtəlif nəticələr və subtle moral choice

**Outcome:** bəzi variantlar var, amma uzunmüddətli hekayə təsiri zəif görünür; exact evidence sistemi seçim hissini azalda bilir.

## Intent: real desktop hissi

**Outcome:** yüksək immersion, amma real OS affordance gözləntiləri də yüksəlir.

## Intent: character-i text davranışından tanıtmaq

**Outcome:** yumor, e-poçt və parody software müsbət qəbul olunur, amma typo/placeholder polish-i zəiflədir.

# 20. Bizim layihə üçün dərslər

1. **Knowledge state first-class olmalıdır.**
2. Eyni cinayəti sübut edən bir neçə məntiqli dəlil route-u qəbul edilə bilməlidir.
3. Failure feedback suspect / evidence / location komponentlərini ayrı göstərməlidir.
4. Wrong answer brute-force üçün pulsuz sonsuz kombinasiya dövrünə çevrilməməlidir.
5. Terminal fantasy-si saxlanırsa, basic editing/history/copy affordance-ları qorunmalıdır.
6. Fictional OS external working memory kimi dizayn edilməlidir.
7. Qeydlər, provenance və case history persistent olmalıdır.
8. Hacking access layer olaraq qısa qalmalı, hər case-də eyni ritual kimi uzanmamalıdır.
9. Realizm deyil, ardıcıl daxili qayda əsasdır.
10. “500 suspect / broad freedom” kimi marketinq ifadələri real sandbox imkanına uyğun olmalıdır.
11. Procedural competence və narrative agency ayrıca dizayn edilməlidir.
12. Case variety yeni reasoning forması yaratmalıdır, yalnız yeni mətn yox.

# Konsept qiymətləndirmə çərçivəsi

## 1. Məqsəd

Bu sənəd research mərhələsindən sonra yaradılacaq oyun ideyalarını eyni meyarlarla müqayisə etmək üçündür.

Bu framework:
- ideya yaratmır;
- winner seçmir;
- yüksək balı avtomatik “et” qərarına çevirmir.

Məqsəd:

> **hansı konseptin əsas janr opportunity-lərini daşıdığını, hansı riskləri erkən yaratdığını və hansı hipotezlərin prototiplə yoxlanmalı olduğunu açıq göstərməkdir.**

---

# 2. Qiymətləndirmə qaydası

Hər konsept 10 əsas kateqoriya üzrə qiymətləndirilir.

Hər kateqoriya:
- 1–5 bal;
- dəlil;
- risk;
- validation plan

ilə doldurulur.

### Bal mənası

| Bal | Mənası |
|---:|---|
| 1 | ciddi zəiflik / konseptlə ziddiyyət |
| 2 | zəif və ya sübutsuz |
| 3 | işləyə bilər, amma risklidir |
| 4 | güclü və dəlillə uyğun |
| 5 | konseptin əsas fərqləndirici gücüdür |

Weighted total:
> qərar üçün siqnal verir, hökm deyil.

---

# 3. Kateqoriyalar və çəkilər

| Kateqoriya | Çəki |
|---|---:|
| A. Rol fantasy-si | 15% |
| B. Core investigation loop | 15% |
| C. Knowledge / reasoning autonomy | 15% |
| D. Agency / consequence | 12% |
| E. Interface-world cohesion | 10% |
| F. Information/character depth | 10% |
| G. Repetition / mastery potential | 8% |
| H. Onboarding / accessibility | 6% |
| I. Market positioning clarity | 5% |
| J. Production / validation feasibility | 4% |
| **Cəmi** | **100%** |

---

# 4. A — Rol fantasy-si (15%)

### Sual
> Oyunçu kimdir və niyə bu işi görür?

### 5 bal
- bir cümlədə aydındır;
- screenshot-dan hiss olunur;
- core verb ilə eynidir;
- fərqləndiricidir.

### 3 bal
- başa düşülür;
- amma çox generic və ya əlavə izah tələb edir.

### 1 bal
- bir neçə zidd rol;
- interface və story başqa fantasy satır.

### Research reference
- Hacknet
- The Operator
- Orwell
- SIMULACRA

### Red flag
> “Əslində oyun bir neçə şeyin qarışığıdır…”

ilə pitch başlayır.

---

# 5. B — Core investigation loop (15%)

### Sual
> Oyunçunun təkrarladığı əsas dövr maraqlı qərar yaradırmı?

### 5 bal
Loop:
- observation;
- relation;
- hypothesis;
- action;
- consequence

yaradır.

### 3 bal
Loop işləyir, amma decision grammar az dəyişir.

### 1 bal
Loop:
- click;
- collect;
- submit

ritualıdır.

### Red flag
30 dəqiqədən sonra tester:
> “indi həmişə bunu edəcəyəm”

deyə bilir.

---

# 6. C — Knowledge / reasoning autonomy (15%)

### Sual
> Oyunçu öz nəticəsini həqiqətən özü qura bilir?

Bu ən vacib kateqoriyalardan biridir.

### 5 bal
- semantic fact state;
- multiple valid evidence;
- alternate routes;
- system player knowledge-ni tanıyır.

### 3 bal
- bəzi açıq reasoning;
- amma critical path script-lidir.

### 1 bal
- exact clue;
- exact query;
- exact file;
- exact trigger.

### Research reference
- Cyber Manhunt
- Mainlining
- Need to Know
- SIMULACRA 3

### Hard gate
Bu kateqoriya **2 və ya aşağıdırsa**, concept prototype validation olmadan irəli aparılmamalıdır.

---

# 7. D — Agency / consequence (12%)

### Sual
> Oyunçunun qərarı world state-i dəyişir?

### 5 bal
- local reaction;
- delayed consequence;
- relationship/info space dəyişir;
- branch real fərqlənir.

### 3 bal
- bəzi meaningful choices;
- çoxu cosmetic.

### 1 bal
- dialogue option fərqlənir;
- nəticə eynidir.

### Red flags
- hidden moral score;
- ending-only consequence;
- “seçmədiyin option sonra yenə deyilir”.

---

# 8. E — Interface-world cohesion (10%)

### Sual
> Interface core theme və rol hissini daşıyır?

### 5 bal
- UI action = world action;
- interface sosial məna ilə theme uyğunlaşır;
- interaction diegetic-dir.

### 3 bal
- yaxşı skin;
- amma bəzi meta-menu layer-lər ayrılır.

### 1 bal
- interface yalnız presentation gimmick-dir.

### Research reference
- Hacknet
- Orwell
- SIMULACRA
- SIMULACRA 3 contrast

---

# 9. F — Information / character depth (10%)

### Sual
> Məlumat yalnız progression token-dir, yoxsa dünyanı/personajı dəyişir?

### 5 bal
- functional;
- explanatory;
- emotional

dəyər birlikdədir.

### 3 bal
- useful clues var;
- character intimacy orta.

### 1 bal
- bütün data quest item kimidir.

### Red flag
> hər sənədin niyə orada olduğunu designer dərhal izah edə bilir, amma world daxilində niyə mövcud olduğu hiss olunmur.

---

# 10. G — Repetition / mastery potential (8%)

### Sual
> Core mechanics yeni vəziyyətlərdə dərinləşir?

### 5 bal
- reusable grammar;
- recombination;
- escalating decisions.

### 3 bal
- variety var;
- mastery orta.

### 1 bal
- single-use mini-games;
- reskin loop.

### Research reference
- Hacknet repetition
- The Operator single-use
- SIMULACRA 3 single-use
- Midnight Protocol tactical reuse

---

# 11. H — Onboarding / accessibility (6%)

### Sual
> İlk sessiya core fantasy-ni tez göstərir?

### 5 bal
- familiar grammar;
- first insight < 20–30 min;
- help without answer leakage.

### 3 bal
- qaydalar bir az ağırdır;
- fantasy görünür.

### 1 bal
- ilk saat qayda/tutorial;
- gameplay payoff gecikir.

### Reference
Cyber Manhunt / Mainlining / SIMULACRA 3 early risk.

---

# 12. I — Market positioning clarity (5%)

### Sual
> Store page-dən dominant gameplay düzgün anlaşılır?

### 5 bal
- one-line hook;
- screenshot clarity;
- actual dominant verb ilə eyni.

### 3 bal
- fərqlənir, amma izah tələb edir.

### 1 bal
- başqa janr gözləntisi yaradır.

### Red flag
Marketing:
> “sandbox”, “hacking sim”, “choices matter”

deyir, system bunu zəif dəstəkləyir.

---

# 13. J — Production / validation feasibility (4%)

### Sual
> Əsas hipotezi kiçik prototiplə yoxlamaq mümkündür?

### 5 bal
- 1 case;
- 2–3 source;
- minimal interface

ilə core value test olunur.

### 3 bal
- orta content dependency.

### 1 bal
- fun yalnız böyük world/content/AI/procedural system tamamlananda görünür.

### Principle
> ən vacib risk ən ucuz prototiplə test edilə bilməlidir.

---

# 14. Hard gates

Weighted score-dan asılı olmayaraq aşağıdakılar varsa concept avtomatik prototip risk review-a gedir.

## Gate 1 — Knowledge autonomy
C ≤ 2

## Gate 2 — Role clarity
A ≤ 2

## Gate 3 — Core loop
B ≤ 2

## Gate 4 — Market mismatch
Store promise ilə actual dominant activity ziddir.

## Gate 5 — Unprototypeable core
Core value yalnız full production-dan sonra test olunur.

---

# 15. Bonus / penalty modifiers

Bunlar əsas baldan sonra ayrıca qeyd olunur.

## Bonus +1 siqnal
- güclü user-generated stories;
- organic replay;
- novel but intuitive interface;
- high social shareability;
- strong creator/streamer moments;
- mod/content extensibility.

## Penalty -1 siqnal
- heavy localization dependency;
- expensive FMV dependency;
- content scale dependency;
- large state explosion;
- platform-specific friction;
- accessibility risk.

Bu modifier final weighted score-u avtomatik dəyişmir; decision discussion üçündür.

# 18. Score interpretation

| Score | Şərh |
|---:|---|
| 85–100 | çox güclü research fit; yenə prototype lazımdır |
| 70–84 | güclü, amma konkret risklər test edilməlidir |
| 55–69 | qarışıq; fundamental fərqləndirici və ya loop problemi ola bilər |
| <55 | research nəticələri ilə ciddi ziddiyyət |

Bu interval:
> investment recommendation deyil.

Sadəcə müqayisə üçün standard dil yaradır.

# 19. Prototype test rubric-i

Konsept paper score-dan sonra ilk prototipdə aşağıdakılar ölçülür.

## T1 — Role comprehension
Tester:
> “Mən kiməm?”

düzgün cavab verir.

## T2 — First insight
Tester ən azı bir real inference qurur.

## T3 — Alternate route
Critical fact ən azı iki üsulla tapıla bilir.

## T4 — Semantic acceptance
Player-supported valid answer qəbul edilir.

## T5 — Consequence visibility
Major action sonrası visible response var.

## T6 — External memory
Tester oyundan kənar note məcburiyyəti hiss etmir.

## T7 — Repetition
30–45 dəqiqədə loop artıq mexaniki hiss olunmur.

## T8 — Guidance
Tester:
> “oyun mənə cavabı dedi”

demir.

---

# 20. Stop / pivot criteria

Prototype aşağıdakı hallarda pivot tələb edir:

1. 30%+ tester doğru reasoning ilə reject olunur.
2. 50%+ tester core role-u yanlış anlayır.
3. İlk meaningful insight median > 30 dəqiqə.
4. Major choice-ların 70%+-i same state verir.
5. Xarici note istifadəsi dominant olur.
6. Hint olmadan progression çox aşağıdır, hint ilə isə answer leakage yaranır.
7. Store promise dominant actual verb ilə uyğun gəlmir.

# 21. Concept comparison qaydası

İki ideyanı müqayisə edəndə:

### Etmə
- “bu daha cool səslənir”;
- feature saymaq;
- yalnız market size-a baxmaq;
- yalnız weighted score seçmək.

### Et
- hard gates;
- biggest uncertainty;
- cheapest falsification test;
- production risk;
- research-backed opportunity

müqayisə et.

### Əsas sual

> **Hansı konsept ən kritik hipotezini ən tez və ən ucuz şəkildə sübut və ya təkzib edə bilər?**

# 23. Yekun

Framework-in məqsədi ən yüksək bal alan idea-nı avtomatik seçmək deyil.

Əsas məqsəd:

> **komandanın niyə bir konsepti digərindən daha güclü hesab etdiyini açıq, müqayisə edilə bilən və prototiplə yoxlana bilən dilə çevirməkdir.**

Research-in ən mühüm constraint-i framework-də də qalır:

> **oyunçu öz reasoning-ni qura bilməli və sistem həmin reasoning-i tanımalıdır.**
